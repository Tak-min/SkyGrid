# Moku 能動化(アンビエント発話)仕様 — 実装用スペック

日付: 2026-09-09
状態: **決定済み・実装開始可**(依頼者との議論で確定。以下は推測ではなく確定事項)
対象: Today画面(ホーム)における Moku の能動的な一言表示機能

## 0. この機能の位置づけ(最重要)

**成功指標は設定しない。** これは意図的な決定である。この機能は growth lever(招待率・課金率などを動かす施策)ではなく、**アニメーション/雰囲気演出機能**として位置づける。したがって:

- 新規の analytics イベントを追加する必要はない。
- A/Bテスト、実験フラグ、効果検証の仕組みは不要。
- `PRODUCT-MODEL.md` の仮説台帳に追加するべき「仮説」ではない(効果を測定しない前提のため)。

これは `PRODUCT-MODEL.md` が全体として「北極星指標→ファネル→仮説」という計測駆動の構成を取っていることと矛盾するように見えるが、依頼者の明示判断であり上書きしない。実装後、`PRODUCT-MODEL.md` の「3. ユーザー動線」に一文で機能の存在を追記する程度でよい(仮説台帳への追加は不要)。

## 1. 絶対的な制約(既存コードから)

### 1.1 課金訴求はこの機能に含めない

`PaywallSecondChanceStepView.swift` に、Mokuが「ちょっと待って、最初の1か月を試してみない?」と語りかける `.pleading` state が既に存在する(second-chance paywall、会議中・一部未実装)。**プラン推奨・アップセル系のセリフは、この paywall 専用の仕組みの領分であり、本機能(Today画面の通常表示)には一切含めない。** 通常画面でユーザーに見える Moku の発話は、buddy活動・写真への感想・アンビエントな一言などの非金銭的な内容のみに限定する。

### 1.2 「常時表示アップセル」の反省を再現しない

`TodayView.swift` には次の設計判断が明記されている:

> 「Free」バッジは常時表示のアップセルの押し付けであり、それはこの画面が目指す『最初の5秒はSNSのフィードやダッシュボードに見えないこと』と正反対だった。だから消した。

依頼者の指示により本機能は「ホーム訪問のたびに確率的に自動表示」で確定している(下記2.1)。ただし**毎回100%表示は上記の反省と衝突するため、確率的トリガーの実装はほどほどの出現率(目安30%前後、要調整可能な定数として実装しておく)とし、1日に何度も出さないための簡易クールダウン(例: 同一カレンダー日には初回表示のみ)を持たせる。** これは依頼者の確定事項(確率的自動表示)への追加提案であり、変更ではない。Codexは定数化しておき、後から依頼者が数値だけ調整できるようにすること。

### 1.3 Mokuのインスタンスは1つのまま

`OnboardingCoordinatorView.swift` および `TodayView.swift` のコメントに明記の通り、「一つの安定したキャラクターが、変化するコンテンツの外側に存在し続ける」という設計原則がある(画面遷移でMokuを重複生成しない)。**本機能でも Moku の SwiftUI インスタンスは Today 画面に1つのまま。** 「表示位置を増やす」とは、Moku自身を複数箇所に複製することではなく、**Mokuに添える吹き出し(セリフ)の アンカー位置(どのセクションの近くに出すか)を毎回ランダムに選ぶ**、という意味で実装する。

## 2. 確定仕様

### 2.1 トリガー

- Today画面訪問のたびに、確率的に自動表示(タップ不要)。
- 出現率は定数化(デフォルト目安 30%、`MokuAmbientMessagePolicy` のような場所に置き、後から調整可能にする)。
- 同一カレンダー日に複数回出さない簡易クールダウンを付ける(1.2参照)。
- Reduce Motion環境では、吹き出しの出現アニメーションを静止表示に縮退させる(既存の `MokuMotionPolicy` パターンに合わせる)。

### 2.2 表示位置(アンカー候補) — ブレインストーミング結果

`TodayView.swift` の実際のセクション構成(`heading` → `morningRecord` → `mosaicEntry` → `buddySection` → `rhythmSection` → `PostStatusBanner`)を踏まえ、アンカー候補を以下まで拡張する。依頼者の当初案(3箇所)より種類を増やす指示に対応:

| # | アンカー | 出現条件 | 想定トーン |
|---|---|---|---|
| 1 | 今日の投稿カード(`morningRecord`)の右上 | 既存デフォルト位置。投稿済み/撮影可能時 | 写真への感想 |
| 2 | buddy投稿欄(`buddySection`)の付近 | buddyが1人以上いる時 | buddy活動への言及 |
| 3 | モザイク/グリッド入口(`mosaicEntry`)の付近 | 常時 | グリッドを覗いてみようという軽い誘い(課金訴求なし、閲覧の誘いのみ) |
| 4 | streak/rhythm セクション(`rhythmSection`)付近 | streakが1以上の時 | 継続を労う一言 |
| 5 | 画面上部の見出し(`heading`)付近 | 常時(post未取得時含む) | 朝の挨拶・アンビエントな一言 |
| 6 | 空状態カード(`emptyMorningRecord`、Day one/streak表示)付近 | 未投稿時 | 今日はどんな空か、という軽い問いかけ |
| 7 | 「Capture the sky」ボタン(撮影導線)付近 | 未投稿時 | 撮影を軽く後押しする一言(義務感を出さない) |
| 8 | 「Share this morning」ボタン付近 | 投稿済み時 | シェアへの軽い誘い |

実装方針: 上記のうち「その時点の状態(投稿有無・buddy有無・streak有無)で出現条件を満たすもの」だけを候補集合とし、その中からランダムに1つを選んでその近くに吹き出しを表示する。候補が1つも無い状態は発生しない設計にする(#5と#6のどちらかは常に成立する)。

### 2.3 メッセージのカテゴリと内容

課金訴求を除き、種類を自律的に増やしてよい(依頼者の明示指示)。最低限、以下のカテゴリを実装した上で、Codexの裁量で同じトーンのバリエーションを追加してよい。既存の `MokuView` のセリフ(例: "One sky is a beginning." のような短く詩的な英語)とトーンを合わせること。

1. **写真への感想**(投稿済み時): 今日撮った空の色・雰囲気に触れる一言。例のトーン: "That blue looks like it earned its morning."
2. **buddy活動への言及**(buddyが実在し、当日投稿がある時に限る。存在しないbuddy活動を語らない): 例のトーン: "Someone in your circle already looked up today."
3. **streak/継続の労い**(streak ≥ 1): 例のトーン: "Three mornings in a row. Quietly impressive."
4. **アンビエント/汎用の一言**(データ非依存、常に出せるフォールバック): 例のトーン: "Skies change their mind a lot before noon."
5. **未投稿時の軽い問いかけ**: 例のトーン: "Wonder what's up there today."
6. **グリッド/モザイクへの軽い誘い**(課金訴求ではなく閲覧の誘いのみ。「見てみたら?」程度に留め、「Proにすれば」等のフレーズを一切含めない): 例のトーン: "Your grid is quietly filling in."

**やってはいけないこと**: 上記のどのカテゴリにも、プラン名・価格・「アップグレード」「Pro」等の課金関連語を含めない。含めた場合は second-chance paywall の領分と重複し、1.1の制約に違反する。

### 2.4 Moku側の状態(`MokuState`)

`.pleading` は second-chance paywall 専用として予約済みのため使わない。本機能では既存の `.ready` / `.delight` / `.settled` を状況に応じて使い分ける(例: 感想・労いは `.delight`、アンビエントな一言は `.ready`)。新しい `MokuState` ケースを増やす必要はない。

## 3. 実装対象と非対象

**対象**
- `ios/SkyGrid/Sources/Today/TodayView.swift` とその周辺(新規の吹き出しコンポーネント、メッセージ選定ロジック、出現条件判定)
- メッセージプールとカテゴリ選定ロジックを持つ新規ファイル(例: `ios/SkyGrid/Sources/Today/MokuAmbientMessage.swift` のような、既存の命名規則に沿った新規ファイル)
- 必要なら `LocalDefaults` への「最終表示日」の保存(クールダウン用)

**非対象(触らないこと)**
- `PaywallSecondChanceStepView.swift` / `SecondChancePaywallPolicy.swift` (未決事項が残っているため、本タスクでは一切変更しない)
- `OnboardingCoordinatorView.swift` 内の companion rail(オンボーディング側のMoku運用は別の仕組みであり、本スペックの対象外)
- Analytics/計測コード(0章の通り不要)
- `MokuState` enum への新規ケース追加

## 4. 受け入れ条件

- Today画面で、条件を満たしたときに確率的にMokuの吹き出しが表示される。
- 吹き出しの位置は2.2の候補の中から、その時点で条件を満たすものだけを対象にランダム選択される。
- 表示されるセリフに課金関連の語が一切含まれない。
- 同一カレンダー日に何度も出ない(クールダウンが機能する)。
- Reduce Motionで静止表示に縮退する。
- Moku SwiftUI インスタンスは画面内で1つのまま(複製されない)。
- 既存のビルド・テストスイート(`SkyGridTests` / `SkyGridUITests`)がグリーンのまま。
