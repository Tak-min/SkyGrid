# SkyGrid マーケティング方針 — Opus 版(2026-09-11)

作成: Claude Code (Opus 5)。依頼: 「開発に専念したい・SNS運用ノウハウなし・動かせるインフルエンサーなし・初期現金3〜5万円」の条件で、
Z世代/10代アプリ開発者の成功事例を調べ、現状の最適解を作る。後で Codex 版と比較する前提。

## 0. 結論(1行)

**今のSkyGridに足りないのは「認知」より先に「本物の友達グラフ」。まず日本の身近な学校で密度を作ってループを証明し、
並行して“本人がほぼ触らない”自動スライドショー工場を回し、勝ったフックだけを少額のマイクロクリエイターに増幅させる。**
現金は最大約4.5万円、依頼者の作業は立ち上げ後「1日5分以内」を上限に設計する。

## 2. 以前の案が外れていた理由(ターゲット設定の誤り)

1. **ターゲットを「朝活・That Girl系の大人」に置いていた。** SkyGridの差別化(相互解禁・Circle)は友達グラフ型であり、
   伸び方の法則は BeReal / Locket / tbh / Gas / Fizz と同じ「密なコミュニティで同時に使い始めさせる」型。
   Nikita Bier(tbh・Gas創業者)のデータでは、**13〜18歳で1歳上がるごとに1人あたり招待送信数が20%落ちる**。
   招待が伸びる層は10代〜学生であり、ライフスタイル系の大人クリエイターは視聴者も含めて一番招待しない層に近い。
2. **自分の周りの友達グラフを使っていなかった。** 依頼者は日本在住で、日本はBeRealの第2の市場(MAU 450万人超・
   日本の高校生の約30%が毎日利用)。「友達と同時に撮る」行動が既にある市場に、アプリが英語のみで入れていない。
3. **レベニューシェア型の打診は、相手に得が見えない。** 実績ゼロのアプリの「売上を分けます」は、報酬がほぼ0と同じ意味になる。
   成功例で機能したのは「少額でも確実に払う」(Blake Anderson: 無名クリエイター2人に各$50)か、「そもそも払わない」(tbh/Gas/Locket)のどちらか。

### 反証・注意点(都合の悪い証拠)

- **Larryは脆い。** 1プラットフォーム依存、会話履歴が長くなると文脈が劣化、ログイン自動化はMFA/CAPTCHAで壊れる(Luminary Lane)。
  Larry本人の結果も、最初は「アプリ機能を語るフック」が879〜2,671再生で失敗し、「他人+対立→見せた→考えが変わった」型に変えてから伸びた。
- **TikTokは2026年にAI生成物のラベル付けと検出を強めている。** 本物の写真を使うスライドショーはラベル対象外になりやすいが、
  AI画像で作ると届く範囲が狭まる恐れがある(公式は「ラベルで配信は減らない」と言うが、2026年3月に順位を下げる変更があったとする記事もある。未検証)。
  → **SkyGridは本物の空の写真が作れるので、AI画像を使わないこと自体が強みになる。**
- **自動化記事の一部は「検出回避」のために中古Android+ADBで公開操作を自動化することを勧めている(Postiz記事)。これは採用しない。**
  プラットフォームの検出を回避する運用はアカウントBANのリスクが大きく、この計画の範囲外。同様に、偽の人格アカウントを量産するやり方も採用しない。
- **バズっても翌週には8割のユーザーが消える**(IsTalk開発者)。一過性の山より、友達ペアの定着(相互解禁のD7)が先。
- **「9回失敗して1回当たる」**(App Mafia)。少額クリエイターは外れる前提で、1人ごとの成否で判断しない。
- 基準値: フリーミアムの無料DL→有料は D35中央値2.1%(北米2.6%)。ハード型ペイウォールは10.7%(RevenueCat 2026)。
  Larryの「50万再生→有料108人」は、ハード型ペイウォール寄りのAIアプリの数字であり、SkyGridにそのまま当てはめない。

## 4. 方針: 3つのエンジンを順番に回す

```
[エンジン1: 密度] 日本の1校で友達グラフを作る → ループが回るか実測
        │ 合格
        ▼
[エンジン2: 自動コンテンツ工場] 本物の空写真スライドショーを自動生成 → 勝ちフックを探す(日英同時)
        │ 勝ちフック発見
        ▼
[エンジン3: 増幅] 勝ちフックだけを10代〜学生のマイクロクリエイターに$30〜50で撮ってもらう
        │ CPI(1インストールあたりの費用)が基準以下
        ▼
[拡大] 売上をそのまま再投資(Cal AI型)+ 学校アンバサダー網(BeReal型)
```

エンジン2はエンジン1と**並行して開始してよい**(依頼者の時間をほぼ使わないため)。エンジン3だけは合格ラインを待つ。

### エンジン1: 密度(日本・自分の学校) — 最優先

- **なぜ**: 相互解禁は「友達が同じ日に撮る」ことが前提。受け手がいない現状では、どれだけ人を呼んでも一人で使うアラームアプリにしかならない。
  PRODUCT-MODEL §5(09-04)の「プロモーション判断より先にD7相互公開率を計測する」とも一致する。
- **やること**
  1. アプリとApp Storeページの**日本語化**(開発タスク。Codex/Claudeに任せられる)。
  2. 依頼者が**友達5〜10人**に招待リンクを送る(「朝アラームを止めるには空を撮るしかないアプリ作った。明日一緒にやって」)。
  3. その5〜10人それぞれが自分のCircleに友達を招待したくなる仕組み: Circle上限5人の無料枠はそのまま。
     **「最初の学校の最初の30人はPro無料」**など、先着の特典を付ける(配布手段はApp Storeのオファーコード等。仕様は要確認)。
  4. 任意: tbh型の学校Instagramアカウント施策は、日本の高校では学校名をbioに書く習慣の強さが未確認なので、1校目は友達経由だけで十分。
- **現金**: 0〜1万円(ローンチ日のお菓子など任意)。**依頼者の作業**: 合計1〜2時間(友達への声かけのみ。SNS投稿なし)。
- **合格ライン(3週間)**: 実ユーザー20人以上 / 招待から翌朝に双方投稿したペア(activated pair)10組以上 / 1週間後も双方投稿しているペアが3組以上。
  母数が小さいので「率」ではなく「実際に起きたか」で判定する。**不合格なら直すのはマーケではなく製品**(招待導線・通知・封印カードの意匠 = バックログ#1)。

### エンジン2: 自動コンテンツ工場(本人の作業は1日5分以内)

- **形式**: TikTok/Instagramのスライドショー、6枚、縦長。素材は**本物の空写真**(依頼者と、許可をくれた友達の写真・アプリ画面)。AI画像は使わない。
  AIに任せるのは、フック文・キャプション・並べ方・投稿後の数字の記録と次のフックの提案だけ。
- **顔を出さない「顔役」はMoku**。キャラクターのアカウントとして運用すれば、依頼者本人が出る必要がない(Duolingoのフクロウ型。効果は未検証の賭け)。
- **フックの型**(Larryで効いた「他人+対立→見せた→考えが変わった」を置き換えたもの。最初はこの3系統だけ試す):
  1. 対立型: 「親に“お前は7時前に起きられない”と言われたので、空を撮るまで止まらないアラームを作った」
  2. 相互解禁型: 「親友は、私が起きて空を撮るまで私の空を見られない」
  3. 積み上げ型: 「30日間、毎朝空を撮った結果」(グリッドが埋まっていく最終スライド)
- **仕組み**: エージェント(Codex/Claude/OpenClaw系)が毎日2〜3本を作り、TikTokの**下書き**としてアップロード(公式APIの下書き機能。Postiz $29/月など)。
  依頼者は**音源を選んで公開ボタンを押すだけ**(1本約1分)。この1分も任せたい場合は、同級生を「公開担当」として少額で頼む(賭け)。
  日本語版と英語版を同じ写真から同時に作る(追加コストはほぼ0)。
- **計測**: bioのリンクを `skygrid.my/get/{placement}` にして、アカウント・言語ごとにクリック数を取る。動画単位の帰属は求めない。
- **現金**: 月約4,500円(Postiz等)× 2か月 ≒ 9,000円。**依頼者の作業**: 初期設定1〜2時間(アカウント作成・本人確認・連携はどうしても本人の操作が必要)+ 1日5分以内。
- **判定(4週間・約60〜80本)**: 1万再生を超える投稿が1本も無ければフックの系統を変える(最大3系統まで)。
  5万再生以上が出たら、そのフックを「勝ちフック」としてエンジン3へ渡す。

### エンジン3: 増幅(勝ちフックが出てから)

- **相手**: フォロワー5千〜5万人の**10代後半〜大学生**クリエイター(朝・学校・勉強・寮生活・「5時起き」系)。
  フォロワー数より、直近の投稿の再生数がフォロワー数を上回っているかを見る。ライフスタイル系の大人の女性アカウントは対象外。
- **条件**: **1本$30〜50の固定払い+10万再生ごとの少額ボーナス**。台本は勝ちフックを渡す(ゼロから考えさせない)。
  レベニューシェアのみの打診はしない。広告であることの表示(TikTokの有料パートナーシップラベル)は必須。
- **現金**: 3人 × $50 ≒ 2.2万円(為替は概算)。**依頼者の作業**: DM文面はエージェントが作り、送信ボタンだけ本人(1人5分)。
- **判定**: 1インストールあたりの費用が約$1.5未満(Apple検索広告の相場$1.4〜4より安い)なら、売上の範囲で本数を増やす。
  上回るなら止めて、エンジン2に戻る。※依頼者が未成年の場合、支払い・契約には保護者の同意が必要になる可能性がある(要確認)。

## 5. 開発側でやること(依頼者が一番得意なところがマーケになる)

優先度順。どれも「広まる仕組みを製品に埋め込む」作業で、SNS運用ではない。

1. **日本語化**(アプリ+App Storeページ)— エンジン1の前提条件。
2. **封印カードの意匠改善**(バックログ#1)— 呼んだ人が最初に触る差別化ポイントが一番安っぽい状態のまま。
3. **共有物すべてにアプリ名と招待リンク/QRを入れる**(年間グリッド・週次まとめ・相互解禁カード)— Locket/IsTalk型の、ユーザーが勝手に宣伝する経路。
4. **週次まとめの動画書き出し**(バックログ#2)— ユーザーの共有がそのままTikTok素材になり、エンジン2の素材にもなる。
5. 計測: `first_open` を分母にした「招待→受諾→翌朝の相互解禁」の週次集計を、アカウント/言語の流入別に読めるようにする。

## 6. スケール後の構想(CEO視点)

- **段階1(〜1か月)**: 1校で密度を作り、ループを実測。自動工場で勝ちフックを探す。
- **段階2(〜3か月)**: 1校で合格したら、その学校の生徒の友達がいる近隣校へ。**学生アンバサダー**に「成立したペア1組ごとに◯円」か「Pro永久無料」で報酬(BeRealは紹介1件$30)。
  「1つのコミュニティで効けば、似たコミュニティ全部で効くはず。効かないなら拡大の信号ではない」(Bier)。
- **段階3(売上が出てから)**: 売上をクリエイター契約へ全額再投資(Cal AI/Quittr型)。英語圏は大学キャンパス単位で同じことをする。
  上限に達したら広告を追加(Cal AIは広告追加で月$2M→$5.7M)。
- **段階4(ブランド)**: Mokuをキャラクターとして育て、夏至・初日の出など「世界中が同じ空を撮る日」をイベント化する。
  イベントの日は、共有物がそのまま大量の投稿になる。

## 7. やらないこと

- レベニューシェアのみでの大人向けインフルエンサー打診の追加。
- AI画像のみのスライドショー、偽の人格アカウントの量産、ADB等で検出を回避する自動公開。
- ループ(エンジン1)が証明される前に、クリエイターや広告にまとまった現金を使うこと。
- 依頼者本人が毎日撮影・編集する前提の計画。

## 8. 変更しない場合の差分(PRODUCT-MODEL 規約)

- 動かす指標: 週あたりの activated pair(招待→受諾→翌朝の双方投稿)数。現在値: **実ユーザーでは0**(受け手がいないため)。
- 変更しない場合: 7件の `first_open` のまま、ファネルの後半が永久に読めず、どの施策が効いたかも判定できない。

## 9. Codex版との比較で見る観点(依頼者がCodexの出力を渡したら使う)

1. ターゲット: 招待を送る層(10代〜学生・密なコミュニティ)に置いているか、それとも大人のライフスタイル層か。
2. 依頼者の作業時間: 施策ごとに「現金」と「依頼者の分数」を分けて書いているか。
3. 予算の現実性: 3〜5万円で実際に買えるものか。月額$299以上のツールや$500最低額の施策が混ざっていないか。
4. 順序: 友達グラフ(ループ)の実証より先にリーチを買っていないか。
5. 根拠: 事例が本文で確認されたものか、検索結果の要約だけか。反証を含むか。
6. 規約リスク: 検出回避・偽アカウント・大量DMなど、アカウント停止リスクの高い施策を含むか。
7. 日本市場: 依頼者が日本在住であることを使っているか。
