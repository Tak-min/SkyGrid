# 写真中心のUI・同期経路レビュー（2026-07-30）

## 観測した問題

- 撮影した画像は `PostDraft`、ローカルoutbox、Firebase Storage に存在するが、Today はStorageへの反映前に平均空色を代替表示していた。
- Sky Grid の表示モデルは `LocalDate -> SkyColor` だけを受け、過去の実写真を確認する導線がなかった。
- full画像の送信成功後にthumb送信が失敗すると、Storage Rulesのcreate-only制約によって次回fullを上書き送信できない可能性があった。
- Buddies、Paywall、Settingsはいずれも機能の列挙が先で、日常で得られる結果・無料でできること・安全な公開条件が読み取りづらかった。

## 実装した判断

1. **画像解決の優先順位**
   - Today: ローカルoutboxのfull画像 → Storageのfull画像。いずれも未到達なら色ではなく同期状態を示すニュートラルなプレースホルダー。
   - Sky Grid: ローカルoutboxのthumb → 32MB上限の端末thumbキャッシュ → Storageのthumb。
   - Grid用画像はImageIOで96pxまでデコードする。選択中の月だけ取得するため、年間画面を開いて365枚のfull画像を取得しない。

2. **過去写真を読めるSky Grid**
   - 年間Canvasは連続性の俯瞰として保持する。
   - 同じ画面に月別写真グリッドと日別フルサイズ表示を置いた。年間の小さなセルを「写真が読める」UIだと誤認しない。
   - 共有カードは意図的に軽量な色の記録として残す。アプリ内アーカイブとは用途を分ける。

3. **同期の再開可能性**
   - `PendingUpload` にfull/thumbそれぞれの完了状態を保存する。部分成功後は未送信variantだけを再送する。
   - 恒久失敗状態を自動drainの対象から外し、Todayに明示的な「Retry now」を表示する。

4. **日常画面の情報設計**
   - TodayのBuddy未接続状態には、公開が「双方の撮影後」であることを説明する招待カードを表示する。
   - Buddiesは招待→撮影→公開を先に説明し、ハンドルを求める理由を明示する。
   - Paywallは無料の最新30日と、Proの実写真アーカイブを分けて説明する。
   - Settingsはアラーム・アーカイブ・安全性・アカウント操作の各結果が一覧で読めるようにした。

## アラームに関する制約

AlarmKitの停止コントロールはシステムが提供するため、アプリが「写真撮影まで停止を拒否する」実装は採らない。既存の副操作でカメラを開く導線を維持し、撮影を促すが、停止そのものを妨げない。これは緊急時の停止操作とプラットフォーム契約を守るためである。

## 参照した競合パターン

- Alarmy: 解除ミッション（写真を含む）で起床行動を促す。
- Rise Alarm Clock: 時刻設定・有効化を単純なジェスチャーに集約する。
- Sleep Cycle: 起床前の時間帯を一つの理解しやすい約束として表示する。

SkyGridでは、競合の「一つの明確な朝の行動」を採りつつ、写真そのものと相互公開のプライバシーを主役にする。

## 残る検証

- Firebase実アカウントで、オフライン撮影→アプリ再起動→通信復旧、full成功/thumb失敗、手動再送を確認する。
- 実写真が入った月別グリッドで、スクロール・日別表示・Pro境界を実機測定する。
- AlarmKitのロック画面、Focus、Apple Watch、時刻更新失敗は実機で確認する。
