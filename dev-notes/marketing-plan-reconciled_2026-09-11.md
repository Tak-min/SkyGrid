# SkyGrid マーケティング実行計画 — Claude版とCodex版の統合(2026-09-11)

入力:
- Claude版: `dev-notes/marketing-strategy-opus_2026-09-11.md`(本文取得22件、出典URLあり)
- Codex版: `SKYGRID_MARKETING_STRATEGY.md`(リポジトリ直下・未追跡。出典は項目名のみでURLなし)

## 1. 両者が一致した点(=確度が高い)

1. 大きなインフルエンサーや広告に最初からお金を使わない。まず「伸びる投稿の型」を見つけ、そこにだけ払う。
2. 全国に薄く撒かず、1つの学校・コミュニティで密度を作る(BeReal・Fizz・tbh型)。
3. ダウンロード数ではなく、朝の撮影・継続・招待で評価する。
4. 共有カード・招待・連続記録を「広まる仕組み」として製品に組み込む。
5. 最初の30日はほとんどお金を使わない(Codex: 1万円以下 / Claude: 月約4,500円+任意の実費)。
6. 対象クリエイターは学生・勉強・朝のルーティン系。大人のライフスタイル系ではない。

## 2. 食い違った点と、統合後の判断

| 論点 | Codex版 | Claude版 | 統合後の判断と理由 |
|---|---|---|---|
| 誰が投稿を作るか | 創業者本人が最初の発信者。14日で30本、2か月目は週5〜7本 | 本物の空写真でAIがスライドショーを作り、本人は公開ボタンだけ | **Claude版を採用。** 依頼者は「動画を作れない・SNSに手を出したくない」と明言している。08-10の「本人が毎日2本・計46本」案が失敗扱いになった経緯とも重なる。Codex版は依頼者の作業時間を一度も見積もっていない |
| 創業者ストーリー | 中心の話題にする(Locket型) | 対立型・相互解禁型・積み上げ型の3系統 | **Codex版の良い点を取り込む。** 「朝起きれなさすぎて高校生がアプリ作った」は強いフック。ただし顔出し動画ではなく、スライドの文字で語る。フックの系統を4つにする |
| クリエイターへの接触量 | 候補300人、1日10〜20件DM、30日で300〜500件 | 勝ちフックが出た後に3人 | **中間を取る。** リスト作成と文面はエージェントが担当し、依頼者は週1回20件だけ送る(約20分/週)。過去の無償DMは12件送って返信0件、レベニューシェアの打診は7件送って依頼者の見込みもほぼ返信なし。数を増やすより、条件(少額でも確実に払う)を変える方が効く |
| 報酬の形 | 固定2,000〜5,000円 + 「有効ユーザー」1人100円(インストール→初回の朝まで完了) | 固定$30〜50 + 再生数ボーナス | **Codex版の型を採用。** 再生数ではなく「実際に朝撮った人」に払う方が目的と一致する。ただし今はクリエイター別に有効ユーザーを数える仕組みがない(アプリ外のリンクのクリック数しか取れない)。そのため**アプリ内の紹介コードを実装するまでは固定額のみ**にする |
| クリエイターの規模 | フォロワー500〜5,000(ナノ) | 5,000〜50,000 | **1,000〜30,000に広げる。** 基準は「直近の再生数がフォロワー数を上回っているか」 |
| 北極星指標 | 週あたりの「成功した朝」 | D7の相互解禁率(PRODUCT-MODELの既存定義) | **既存のD7相互解禁率を維持し、成功した朝は補助指標にする。** SkyGridの差別化は相互解禁。一人の朝だけを数えると普通のアラームアプリと区別できない |
| 学校内ランキング | 「School leaderboard」「クラスで一番長く続ける」 | 触れていない | **保留(依頼者の判断が必要)。** `DESIGN.md:37` と `VISION.md` §6 がランキングを明示的に禁止している。変えるなら設計方針の変更になる |
| 日本市場 | 高専・朝活など日本前提の例が多いが、アプリが英語のみである点に触れていない | 日本語化を最初の前提条件にした | **日本語化を最優先の開発タスクにする。** 日本の学校で密度を作るなら必須 |
| 法律 | 日本のステマ規制(景品表示法、2023年10月施行)に言及 | TikTokの有料パートナーシップ表示のみ | **Codex版の指摘を採用。** 金銭・Pro無料・ギフトを渡して投稿してもらう場合は「#PR」等の表示を必須にする。Claude版の抜けだった |
| 根拠 | 事例名のみ(Cal AI・Locket・BeReal・ten ten)。URLや数値がない | 本文を取得した22件+反証 | Codex版のCal AIの「大量DM」「Googleシートで管理」、ten tenの事例は本文で確認していない。**判断の根拠にはしない** |

## 3. 統合後の実行計画

### 第0週〜第2週: 準備(大半は開発)

| # | 作業 | 担当 | 現金 | 依頼者の時間 |
|---|---|---|---|---|
| 1 | アプリとApp Storeページの日本語化 | エージェント(Codex/Claude) | 0 | 確認のみ |
| 2 | 共有カード(1日分・週次・年間・相互解禁)にアプリ名と招待リンクを入れる | エージェント | 0 | 確認のみ |
| 3 | オンボーディングに任意の「紹介コード」欄を追加し、どのクリエイター・アンバサダー経由で「最初の朝」まで進んだ人がいるかを数えられるようにする | エージェント | 0 | 確認のみ |
| 4 | 封印カードの見た目の改善(バックログ#1) | エージェント | 0 | 確認のみ |
| 5 | TikTok/Instagramのアカウント開設・本人確認・投稿ツール(Postiz等)との連携 | **依頼者本人**(代行不可) | 月約4,500円 | 1〜2時間(1回だけ) |
| 6 | 友達5〜10人に招待リンクを送る(日本語版の配信後) | **依頼者本人** | 0〜1万円(任意) | 30分〜1時間 |

### 第2週〜第6週: 検証

- **学校内の密度**: 合格ラインは、実ユーザー20人以上 / 翌朝に双方が投稿したペア10組以上 / 1週間後も続いているペア3組以上。
  届かなければ、宣伝ではなく製品(招待・通知・封印カード)を直す。
- **自動スライドショー**: 1日2〜3本、日英同時。フックは4系統(創業者ストーリー・対立型・相互解禁型・積み上げ型)。
  依頼者の作業は、音源を選んで公開するだけ(1日5分以内)。
  判定: 約60〜80本で1万再生を超える投稿がなければ系統を入れ替える。5万再生を超えたらその型を「勝ち型」として次へ。
- **クリエイター候補リスト**: エージェントが100人分作る。依頼者は週20件だけ送信。

### 第6週〜第12週: 増幅

- 勝ち型を、学生クリエイター3〜5人に「固定2,000〜5,000円(紹介コード実装後は+有効ユーザー1人100円)」で依頼する。#PR表示は必須。
- 学校で合格したら、その学校のアンバサダーに「成立したペア1組ごとの報酬」か「Pro永久無料」を渡し、近隣校へ広げる。
- 1人の有効ユーザーを得るのにかかった費用を計算し、安い経路にだけ残りの予算を回す。

### 予算(上限5万円)

| 項目 | 金額 | 時期 |
|---|---|---|
| 投稿ツール 3か月 | 約13,500円 | 第2週〜 |
| 学校ローンチの実費 | 0〜10,000円 | 第2週(任意) |
| クリエイター3〜5人 | 約15,000〜20,000円 | 勝ち型が出てから |
| 予備(勝ったクリエイターの追加依頼) | 残り | 1人あたりの費用が基準以下の時だけ |

## 4. 依頼者に決めてもらうこと

1. 日本の学校から始めるか(=日本語化を最優先にするか)。推奨: はい。
2. 公開ボタンを押す1日5分を自分でやるか、同級生に少額で頼むか。
3. 学校内ランキングを入れるか(現在の設計ルールでは禁止)。推奨: 最初は入れない。「今朝この学校で◯人が空を撮った」という人数表示なら、順位を付けずに同じ効果が狙える。

## 5. 未検証

- Codex版の事例(Cal AIの大量DM、ten ten)は本文で確認していない。
- クリエイターが有効ユーザー1人100円の条件を受けるかは不明(実績ゼロのアプリの成果報酬は、相手から見て価値が低い可能性がある)。
- 投稿ツールの料金、App Storeで無料特典を配る仕組みの現行条件、依頼者が未成年の場合の支払い・契約手続き。
